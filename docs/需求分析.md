## 1. 背景与目标

### 1.1 背景

日常存在大量「将视频保存到本地」的需求，但常见平台存在以下痛点：

- 官方不提供下载，或下载入口隐蔽
- 不支持批量、清晰度受限、移动端体验差
- 跨平台操作成本高，工具碎片化

### 1.2 产品目标

开发一个**学习向**的万能视频下载网站，做到：

1. **更快**：粘贴链接 → 解析 → 选清晰度 → 下载，路径尽量短
2. **随时随地**：Web 形态，手机与桌面均可使用
3. **多平台**：凡 [yt-dlp](https://github.com/yt-dlp/yt-dlp) 支持的站点均可解析/下载，不自行维护各站爬虫
4. **可扩展**：为视频总结、字幕翻译、付费能力预留 UI 与产品位
5. **可转化**：界面突出实用价值与付费意愿（视觉与文案），第一版不接真实支付

### 1.3 非目标（本期不做）

- 真实支付 / 会员体系 / 用户账号体系
- 真实 AI 总结、字幕翻译能力
- 数据库持久化、后台运营系统
- 阿里云生产部署方案、CDN、域名备案等
- 自研各平台解析器或修改 yt-dlp 源码

## 2. 干系人与使用约束

| 角色 | 诉求 |
|------|------|
| 学习者 / 开发者 | 理解「薄封装开源能力 + 现代前后端」的开发模式 |
| 终端用户（本机） | 快速解析并下载视频到本地 |
| 产品方 | 界面有付费产品感，便于后续加增值能力 |

### 2.1 版权与合规（必须遵守）

- 产品定位为**学习与个人备份辅助**，须在显著位置声明：仅供学习，请尊重版权，禁止下载未授权内容用于商用或传播。
- **不**引导用户绕过 DRM、破解会员、盗取账号；**不**默认收集或要求上传 Cookie/密码（若日后需要登录态站点，仅限本机本地配置，本期不做）。
- 公网部署存在限流、封 IP、法律与平台封禁风险；本期按本机使用设计，文档中需提醒后续上线风险。
- 默认关闭播放列表整页抓取（`noplaylist`），降低误下大量内容的风险。

## 4. 用户故事与场景

### 4.1 核心故事（P0）

| ID | 作为… | 我想要… | 以便… |
|----|--------|---------|--------|
| US-01 | 用户 | 粘贴视频链接并一键解析 | 看到标题、封面、时长、可选格式 |
| US-02 | 用户 | 从格式列表中选择清晰度/封装 | 按需下载合适体积与画质 |
| US-03 | 用户 | 在浏览器中触发下载并拿到文件 | 保存到本机（含手机浏览器） |
| US-04 | 用户 | 在手机上完成上述流程 | 随时随地使用 |
| US-05 | 用户 | 看到清晰的失败原因 | 知道是链接无效、站点不支持还是临时失败 |

### 4.2 体验与转化故事（P1，第一版交付 UI）

| ID | 作为… | 我想要… | 以便… |
|----|--------|---------|--------|
| US-06 | 访客 | 看到支持平台/能力展示 | 建立「万能」认知并愿意尝试 |
| US-07 | 访客 | 看到「视频总结 / 字幕翻译 / 会员」入口 | 感知增值能力（可灰显或「即将上线」） |
| US-08 | 访客 | 看到版权与使用声明 | 明确合规边界 |

### 4.3 典型流程

```
打开网站 → 粘贴 URL → 点击「解析」
    → 展示封面 / 标题 / 时长 / 格式列表
    → 选择清晰度 → 点击「下载」
    → 后端调用 yt-dlp 下载到临时目录
    → 浏览器获得文件流 / 下载链接 → 保存到本地
```

异常路径：空链接、非法 URL、yt-dlp 无提取器、私密/下架视频、网络超时、ffmpeg 缺失导致合并失败等，均需可读错误提示。

## 5. 功能需求

### 5.1 功能清单

| 模块 | 需求 | 优先级 | 第一版 |
|------|------|--------|--------|
| 链接解析 | 输入 URL，返回元数据与可选格式 | P0 | ✅ 实现 |
| 清晰度选择 | 展示 format 列表（分辨率/编码/大小等可得字段） | P0 | ✅ 实现 |
| 视频下载 | 按选定 format 下载并提供给浏览器 | P0 | ✅ 实现 |
| 移动端适配 | 响应式布局，手机可完成全流程 | P0 | ✅ 实现 |
| 平台能力展示 | Pill/卡片展示常见平台（实际能力以 yt-dlp 为准） | P1 | ✅ UI |
| 合规声明 | 页脚/弹层版权与学习用途说明 | P0 | ✅ 实现 |
| 视频总结 | 字幕 + LLM 摘要 / 章节 / 要点 | P2 | ✅ 首版（见 docs/AI视频总结方案设计.md） |
| 字幕翻译 | 入口与说明 | P2 | 🔲 UI 占位 |
| 付费/会员 | 价格或权益展示、CTA | P2 | 🔲 UI 占位 |
| 批量下载 | 多链接队列 | P2 | ❌ 不做 |
| 用户登录 | 账号体系 | P2 | ❌ 不做 |
| 历史记录 | 持久化历史 | P2 | ❌ 不做（无库） |

### 5.2 解析结果字段（期望）

从 yt-dlp `extract_info(..., download=False)` 经 `sanitize_info` 后对外暴露精简字段，例如：

| 字段 | 说明 |
|------|------|
| `id` | 视频 ID |
| `title` | 标题 |
| `thumbnail` | 封面 URL |
| `duration` | 时长（秒） |
| `uploader` | 作者（可选） |
| `webpage_url` | 原始页面 |
| `extractor` / `extractor_key` | 来源站点标识 |
| `formats[]` | 可选格式：`format_id`、`ext`、`resolution`、`fps`、`vcodec`、`acodec`、`filesize`/`filesize_approx`、`format_note` 等 |

前端仅展示对用户有意义的格式（可过滤纯故事板、过小预览流等，规则在方案设计中约定）。

### 5.3 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 解析尽量秒级反馈（取决于目标站）；下载进度可后续增强，第一版至少有「下载中」状态 |
| 并发 | 本机学习场景，限制同时下载任务数（如 1～2），避免打满磁盘/带宽 |
| 安全 | 校验 URL；禁止任意路径读写；下载目录隔离；不执行用户传入的 shell |
| 清理 | 临时文件定时或下载后延迟删除，避免磁盘占满 |
| 可维护 | 业务代码尽量薄，下载逻辑委托 yt-dlp；依赖与启动步骤写清 README |
| 兼容 | 现代浏览器（Chrome / Safari / Edge 近两年版本）；需本机安装 ffmpeg 以支持音视频合并 |

## 6. 界面与体验需求

### 6.1 设计参照

模仿 [AI 绘图提示词站](https://ai.codefather.cn/painting) 的视觉语言，但内容改为下载产品：

- 白底 + 品牌蓝（约 `#1777FF`）主操作色
- 大圆角 / 胶囊搜索与按钮
- 首屏：标题（关键词蓝色高亮）+ 一句卖点 + 大输入条
- 状态/能力胶囊条、多行 Pill 标签（可带 emoji）
- 圆角卡片网格展示能力或示例平台
- 手机优先，桌面顶栏 + 内容区

### 6.2 信息架构（第一版页面）

1. **顶栏**：品牌名「万能视频下载器」、简单导航（下载 / 进阶能力锚点）
2. **Hero**：主标题 + 副文案 + URL 输入 +「解析」按钮
3. **平台/能力 Pill**：展示覆盖面（文案可写「基于 yt-dlp，支持千站」）
4. **结果区**：解析成功后展示封面、元信息、格式选择、下载按钮
5. **进阶能力区（占位）**：视频总结、字幕翻译、会员特权卡片 +「即将上线」
6. **页脚**：版权声明、学习用途、风险提示

### 6.3 文案方向（转化向）

- 强调：更快、更清晰、多平台、手机也能下
- 付费占位：批量加速、高清优先队列、AI 总结/字幕等（不承诺第一版可用）
- 避免夸大「破解」「免费看会员」等违规话术

## 8. 验收标准（第一版）

### 8.1 功能与体验结果

1. 本机按文档启动前后端后，可打开 Web 页面。
2. 任选 yt-dlp 支持的公开可访问视频链接，能成功**解析**出标题与格式列表。
3. 选择某一清晰度后能**下载**到本地可播放文件（若需合并，本机已装 ffmpeg）。
4. 手机宽度布局下可完成粘贴、解析、下载操作。
5. 页面存在总结 / 翻译 / 付费的 **UI 占位**，不要求功能可用。
6. 页面有明确版权与学习用途声明。
7. 错误链接或解析失败时有明确中文提示，不白屏、不裸堆栈给用户。

### 8.2 自主测试方式（提请验收前必做）

开发完成后，实现方须先完成自主测试，再找人工验收，其中：

1. **接口自测**：健康检查、解析、下载、非法链接等 API 用例（详见《方案设计.md》§9.1）。
2. **浏览器点击端到端自测（必做）**：打开前端页面，**实际粘贴链接、点击「解析」、选择清晰度、点击「下载」**，并覆盖失败提示、窄屏主流程、占位与合规展示（详见《方案设计.md》§9.2 E2E-1～E2E-6）。
3. 仅调 API、不打开浏览器点击，**不算**自主测试完成，不得提请验收。
4. 人工验收同样以浏览器实操主流程为准，与上列结果标准一致。

## 9. 风险与假设

| 风险 | 说明 | 缓解 |
|------|------|------|
| 站点反爬 / 接口变更 | yt-dlp 偶发失效 | 升级 yt-dlp；产品侧提示「请更新引擎」 |
| 无 ffmpeg | 部分格式无法合并 | README 写明安装；错误提示引导安装 |
| 磁盘占满 | 大文件临时存放 | 目录隔离 + 过期清理 + 并发限制 |
| 法律与版权 | 用户滥用 | 显著声明 + 学习定位 + 默认 noplaylist |
| 后续公网部署 | IP 被封、合规压力 | 本期仅本机；上线前单独评估 |

**假设**：开发与验收环境已安装 Python 3.10+、Node.js（LTS）、ffmpeg，并可访问目标视频站点。
