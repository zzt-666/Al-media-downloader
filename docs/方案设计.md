## 1. 设计原则

1. **站在巨人肩膀上**：下载与解析全部委托 [yt-dlp](https://github.com/yt-dlp/yt-dlp)，业务侧只做薄封装，不 fork、不改其源码。
2. **尽量少代码**：后端 = FastAPI 路由 + yt-dlp 调用 + 临时文件管理；前端 = 单页主流程。
3. **无数据库**：任务与文件用内存 + 本地目录；进程重启后内存态清空可接受（学习场景）。
4. **本机优先**：先保证本机可跑通；阿里云部署留待后续，本期不设计生产架构。
5. **UI 可转化**：视觉对齐 painting 站风格，进阶能力仅占位，不阻塞主链路。

## 2. 技术架构

### 2.1 总览

```
┌─────────────────────────────┐
│  浏览器（手机 / 桌面）         │
│  Vue 3 + Vite + Tailwind     │
└──────────────┬──────────────┘
               │ HTTP/JSON + 文件下载
┌──────────────▼──────────────┐
│  FastAPI                      │
│  /api/parse  /api/download …  │
└──────────────┬──────────────┘
               │ YoutubeDL API
┌──────────────▼──────────────┐
│  yt-dlp (+ 系统 ffmpeg)       │
│  各站点 InfoExtractor         │
└──────────────┬──────────────┘
               │
        downloads/ 临时文件
```

### 2.2 技术选型

| 层级 | 技术 | 说明 |
|------|------|------|
| 前端 | Vue 3 + Vite + Tailwind CSS | 按确认替换原 React 方案；组件少、单页即可 |
| 后端 | Python 3.10+ / FastAPI / Uvicorn | 轻量 API、静态资源可同源或分端口开发 |
| 下载引擎 | `yt-dlp`（PyPI 包） | `YoutubeDL.extract_info` / 下载 |
| 媒体处理 | 系统 `ffmpeg` | 部分 format 需合并音视频 |
| 存储 | 本地目录 `downloads/` | 无 Redis / 无 SQL |
| 包管理 | 后端 `requirements.txt`；前端 `pnpm` 或 `npm` | 以仓库内锁定文件为准 |

### 2.3 为何不用「改 yt-dlp 源码」

yt-dlp 已提供稳定 Python API，CLI 参数与 options dict 一一对应。Web 服务只需：

- `extract_info(url, download=False)` → 解析
- `extract_info(url, download=True)` 或等价下载路径 → 落盘
- `sanitize_info(info)` → 可 JSON 序列化后再裁剪字段返回前端

这是改动最小、升级成本最低的方式：升级引擎 ≈ `pip install -U yt-dlp`。

## 4. 后端设计

### 4.1 模块职责

| 模块 | 职责 |
|------|------|
| `config.py` | `DOWNLOAD_DIR`、最大并发、文件 TTL、允许的 URL scheme |
| `ytdlp_service.py` | 解析、下载、格式过滤/排序、错误映射 |
| `routes.py` | HTTP 入参校验、调用 service、返回 JSON 或 `FileResponse` |
| `schemas.py` | `ParseRequest`、`ParseResponse`、`DownloadRequest` 等 |

### 4.2 yt-dlp 封装约定

**解析（不下载）：**

```python
opts = {
    "quiet": True,
    "noplaylist": True,
    "skip_download": True,
}
with YoutubeDL(opts) as ydl:
    info = ydl.extract_info(url, download=False)
    data = ydl.sanitize_info(info)
```

**下载：**

```python
opts = {
    "quiet": True,
    "noplaylist": True,
    "format": format_id,  # 用户选择的 format_id，或 "bv*+ba/b" 等回退
    "outtmpl": str(download_dir / "%(id)s_%(format_id)s.%(ext)s"),
    "paths": {"home": str(download_dir)},
}
with YoutubeDL(opts) as ydl:
    info = ydl.extract_info(url, download=True)
    # 优先从 requested_downloads[0]['filepath'] 取真实路径
```

**注意：**

- 序列化前必须 `sanitize_info`。
- 合并/后处理后，文件路径以 `requested_downloads` 为准，不要只信 `prepare_filename`。
- 捕获 `yt_dlp.utils.DownloadError`，转成对用户友好的中文 `detail`。

### 4.3 格式列表策略

- 从 `formats` 中过滤明显无用项（如 `filesize` 极小且无视频轨的 storyboard，若可识别）。
- 排序建议：有视频轨优先 → 分辨率从高到低 → 文件大小。
- 前端展示：`format_id`、分辨率、`ext`、`format_note`、大约大小。
- 若用户不选，可提供默认「最佳」：`bv*+ba/b`（需 ffmpeg）。

### 4.4 任务与文件（无库）

第一版推荐**同步下载接口**（学习场景够用）：

1. `POST /api/download` 阻塞至文件就绪（设合理超时，如 5～10 分钟可配置）。
2. 成功后返回 `file_id`，或直接以附件流返回。
3. 内存 dict：`file_id → {path, created_at, title, ext}`。
4. 后台线程或启动时扫描：删除超过 TTL（如 1 小时）的文件。

若同步体验过差，可升级为：

- `POST /api/download` → `task_id`（queued）
- `GET /api/tasks/{id}` → 进度/状态
- `GET /api/files/{id}` → 文件

第一版优先同步 + `file_id` 二次拉取，代码更少；若验收时体验不足再加轮询。

### 4.5 API 设计

#### `GET /api/health`

```json
{ "ok": true, "yt_dlp": "版本号", "ffmpeg": true }
```

用于自检依赖是否齐全。

#### `POST /api/parse`

请求：

```json
{ "url": "https://..." }
```

响应（示例结构）：

```json
{
  "id": "xxxx",
  "title": "...",
  "thumbnail": "https://...",
  "duration": 123,
  "uploader": "...",
  "webpage_url": "https://...",
  "extractor": "Youtube",
  "formats": [
    {
      "format_id": "137+140",
      "ext": "mp4",
      "resolution": "1080p",
      "fps": 30,
      "vcodec": "avc1...",
      "acodec": "mp4a...",
      "filesize": 12345678,
      "format_note": "1080p"
    }
  ]
}
```

错误：`400` 非法 URL；`422` 校验失败；`502`/`400` 解析失败（带 `detail`）。

#### `POST /api/download`

请求：

```json
{
  "url": "https://...",
  "format_id": "137+140"
}
```

`format_id` 可空，空则用默认最佳。

响应：

```json
{
  "file_id": "uuid",
  "filename": "标题.mp4",
  "size": 12345678
}
```

#### `GET /api/files/{file_id}`

- `FileResponse`，`Content-Disposition: attachment`
- 不存在或过期 → `404`

#### CORS

开发期允许前端 Vite 源（如 `http://127.0.0.1:5173`）。本机可两端口联调。

### 4.6 安全与限流（轻量）

| 项 | 做法 |
|----|------|
| URL | 仅 `http`/`https`；拒绝 `file://` 等 |
| 路径 | 下载文件名由服务端生成；`file_id` 用 UUID，禁止 `../` |
| 并发 | 全局信号量限制同时下载数（建议 1） |
| 体积 | 可选：拒绝超大 `filesize_approx`（可配置，默认宽松） |
| 输入 | 不接受用户自定义 `outtmpl` / 任意 yt-dlp 原始 options |

## 6. 数据流

### 6.1 解析

```
用户粘贴 URL
  → POST /api/parse
  → ytdlp_service.parse(url)
  → sanitize + 裁剪 formats
  → 前端渲染 ParseResult
```

### 6.2 下载

```
用户选择 format_id，点击下载
  → POST /api/download { url, format_id }
  → ytdlp_service.download(...)
  → 写入 downloads/，登记 file_id
  → 前端 GET /api/files/{file_id}（或 window.open / a[download]）
  → 浏览器保存文件
```

## 7. 错误处理映射

| 场景 | 用户可见文案（示例） |
|------|----------------------|
| URL 为空/非法 | 请输入有效的 http(s) 视频链接 |
| 无合适提取器 | 暂无法识别该链接，请确认是否为 yt-dlp 支持的站点 |
| 视频不可用 | 视频不存在、已删除或无权访问 |
| 网络/超时 | 解析或下载超时，请稍后重试 |
| 缺 ffmpeg | 需要本机安装 ffmpeg 才能合并该清晰度 |
| 文件过期 | 文件已清理，请重新下载 |
| 并发占满 | 已有任务进行中，请稍后再试 |

后端日志可保留英文原始异常，响应只给中文 `detail`。

## 8. 依赖与运行（本机）

### 8.1 系统依赖

- Python 3.10+
- Node.js 18+（或当前 LTS）
- ffmpeg（加入 PATH）

### 8.2 后端

```bash
cd backend
python -m venv .venv
# Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

主要 Python 依赖：`fastapi`、`uvicorn`、`yt-dlp`、`pydantic` 等。

### 8.3 前端

```bash
cd frontend
npm install
npm run dev
```

Vite 将 `/api` 代理到 `http://127.0.0.1:8000`。

### 8.4 健康检查

打开或请求 `GET /api/health`，确认 `yt_dlp` 版本与 `ffmpeg: true`。

## 9. 测试与验证计划

开发启动后由实现方**自主验证通过后**，再提请人工验收。验证分两层：**接口自测** + **浏览器点击端到端自测**；后者为提请验收前的必做项，不可仅用 API 调用代替。

### 9.1 接口自测（API）

| 用例 | 步骤 | 期望 |
|------|------|------|
| T1 健康检查 | 请求 `GET /api/health` | ok，含 yt-dlp 版本；尽量确认 ffmpeg |
| T2 解析公开视频 | `POST /api/parse` 传入公开可访问 URL | 返回标题与 formats |
| T3 下载 | `POST /api/download` 后拉取文件 | 本地文件可播放 |
| T4 非法链接 | 空串 / `not-a-url` | 友好中文错误，非裸堆栈 |
| T5 不支持/不可用 | 非媒体页或无效媒体页（视 yt-dlp） | 友好中文错误 |

### 9.2 浏览器点击端到端自测（必做）

实现方须**启动前后端**，用浏览器（Cursor Browser 或本机 Chrome 等）打开前端地址，**真实点击**完成下列用例，不得只测 API。

| 用例 | 步骤 | 期望 |
|------|------|------|
| E2E-1 页面打开 | 打开前端首页 | Hero、输入框、「解析」按钮可见，无白屏 |
| E2E-2 解析成功 | 粘贴公开视频 URL → **点击「解析」** | 出现封面/标题/时长与清晰度列表；有 loading 再出结果 |
| E2E-3 选清晰度下载 | 选择某一格式 → **点击「下载」** | 有下载中状态；浏览器开始保存文件；文件可播放 |
| E2E-4 解析失败提示 | 输入非法链接 → **点击「解析」** | 页面内中文错误提示，不白屏 |
| E2E-5 移动宽度 | 将视口收窄至手机宽度，重复 E2E-2（及尽量 E2E-3） | 布局可用，主按钮可点，流程可完成 |
| E2E-6 占位与合规 | 滚动查看进阶区与页脚 | 总结/翻译/付费占位可见且标明未上线；有版权与学习声明 |

**执行要求：**

1. 须实际操作页面控件（输入、点击解析、选择格式、点击下载），截图或文字记录结果均可，作为提请验收前的自证。
2. 测试链接须**有权访问、符合学习用途**的公开内容；文档不固化具体 URL（避免失效）。
3. S4 完成以「§9.1 + §9.2 均通过」为准，再提请你验收；你验收时同样以浏览器实操为主。

## 13. 小结

本方案用 **FastAPI 薄封装 yt-dlp + Vue 产品化前端**，在无数据库前提下交付「解析 → 选清晰度 → 下载」主链路，并用 painting 风格 UI 承载转化与合规信息。实现时优先保证 `ytdlp_service` 正确、API 稳定、前端主流程顺滑；占位功能与上云事项不进入第一版开发范围。
